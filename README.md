# Lead Scoring System

An end-to-end machine-learning pipeline that downloads CRM leads and followups
from the Shetec API, engineers numeric and narration/NLP features, trains an
XGBoost regression model, and returns a lead score from 1 to 100.

The project currently uses a **proxy score** generated by the feature
engineering rules as its training target. It does not yet use manually
verified conversion labels.

## What the project does

1. Downloads leads and their followups using HTTP Basic Authentication.
2. Groups followups by lead and stores the raw API responses as JSON.
3. Builds lead, followup, budget, engagement, stage, interest, and narration
   features.
4. Generates a proxy score from CRM fields and followup text.
5. Trains an `XGBRegressor` with cross-validation.
6. Scores one lead, a CSV batch, all downloaded leads, or an interactive input.
7. Optionally exposes scoring through a Flask REST API.

The scripts and the `data` and `models` folders are at the project root.
There is no `src/` folder and there is currently no `requirements.txt` file.

## Requirements

- Python 3.10 or newer
- Network access to the configured Shetec API for data download
- API username and password
- Python packages:
  - `requests`
  - `pandas`
  - `numpy`
  - `scikit-learn`
  - `xgboost`
  - `joblib`
  - `matplotlib`
  - `flask`
  - `shap` (optional; enables additional SHAP charts during training)

## Installation

From PowerShell, open the project directory and create a virtual environment:

```powershell
cd "D:\lead scoring"
py -3.10 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
python -m pip install requests pandas numpy scikit-learn xgboost joblib matplotlib flask
```

Optional explainability support:

```powershell
python -m pip install shap
```

If PowerShell blocks activation, either allow scripts for the current user or
run the scripts using the virtual environment's interpreter directly:

```powershell
.\.venv\Scripts\python.exe step2_feature_engineering.py
```

## Configure API access

Before running the downloader, edit the `USERNAME` and `PASSWORD` constants at
the top of `step1_download_data.py`:

```python
USERNAME = "your-api-username"
PASSWORD = "your-api-password"
```

The current endpoints are:

- Leads: `https://shetec.com.pk/ace_properties/api/v1/MobileApp/GetAllLeads`
- Followups:
  `https://shetec.com.pk/ace_properties/api/v1/MobileApp/GetAllLeadsFollowups?LeadId`

The downloader requests up to 5,000 leads in pages of 50 and then makes one
followup request per lead. Adjust `PAGE_SIZE` or `MAX_LEADS` in
`step1_download_data.py` if required. Do not commit real credentials to source
control.

## Run the complete pipeline

Run these commands from the project root and in this order:

```powershell
# Activate the environment if it is not already active
.\.venv\Scripts\Activate.ps1

# 1. Download leads and followups
python step1_download_data.py

# 2. Build the ML feature table
python step2_feature_engineering.py

# 3. Train the model and generate reports/charts
python step3_train_model.py

# 4. Score an example lead
python step4_predict.py --lead lead.json --followups followups.json
```

If `python step4_predict.py` reports `No module named 'xgboost'`, the
`python` command is using a different interpreter from the project
environment. Run the script explicitly with the environment that has the
dependencies installed:

```powershell
.\venv\Scripts\python.exe step4_predict.py --lead lead.json --followups followups.json
```

Alternatively, activate the environment first:

```powershell
.\venv\Scripts\Activate.ps1
python step4_predict.py --lead lead.json --followups followups.json
```

Steps 2 and 3 require the output of the preceding step. Step 4 requires the
model files generated by step 3.

### Step 1: Download data

```powershell
python step1_download_data.py
```

This paginates through the leads endpoint, fetches followups using each lead's
ID and client/member ID, retries common HTTP/network failures, and writes:

- `data/leads_raw.json` - raw lead records
- `data/followups_raw.json` - one flat list of followups
- `data/followups_by_lead.json` - followups keyed by lead ID

If no leads are returned, check the credentials, endpoint availability, and
the field names printed by the script.

### Step 2: Feature engineering

```powershell
python step2_feature_engineering.py
```

This reads the two grouped JSON inputs and writes:

- `data/features.csv`
- `data/feature_columns.json`

The current generated dataset contains 66 model features, including:

- Lead stage, interest, source, purpose, status, budget, and date features
- Followup count, recency, frequency, meeting quality, calls, postponements,
  stage changes, and interest trends
- Narration keyword signals for payments, bookings, intent, site visits, and
  negative engagement

Only leads with usable followup history are included in the training table.

### Step 3: Train the model

```powershell
python step3_train_model.py
```

The script scales the feature matrix with `RobustScaler`, trains an XGBoost
regressor with K-fold cross-validation, prints MAE/R2/bucket metrics, and
writes:

- `models/xgb_lead_scorer.model`
- `models/scaler.pkl`
- `models/training_report.json`
- `models/feature_importance.png`
- `models/score_distribution.png`
- `models/cv_fold_results.png`
- `models/actual_vs_predicted.png`
- `models/bucket_breakdown.png`
- `models/narr_signal_analysis.png`
- `models/shap_importance.png`, `models/shap_bar.png`, and
  `models/shap_narr_bar.png` when `shap` is installed

The target is a rule-based proxy score, so the reported metrics measure how
well the model reproduces that proxy rather than real-world conversion
probability.

## Predicting scores

### Single lead

The `--lead` file contains one JSON object. Followups are optional:

```powershell
python step4_predict.py --lead lead.json --followups followups.json
python step4_predict.py --lead lead.json
```

The command prints the lead ID, numeric score, score tier, recommendation, and
the most influential factors.

### Batch prediction

The batch input is a CSV containing lead columns understood by the feature
builder. The followups file may be a JSON list or a dictionary keyed by lead
ID:

```powershell
python step4_predict.py `
  --batch leads_batch.csv `
  --followups followups_by_lead.json `
  --output predictions.csv
```

### Score all downloaded leads

After step 1 and step 3:

```powershell
python step4_predict.py --score-all --output all_predictions.csv
```

This reads `data/leads_raw.json` and
`data/followups_by_lead.json`, then writes a CSV of predictions.

### Interactive mode

```powershell
python step4_predict.py --interactive
```

The program prompts for a lead JSON path and an optional followups JSON path
until `quit` is entered.

### Python usage

```python
from step4_predict import predict_score

lead = {
    "LeadNo": 3678,
    "InterestLevel": "Medium",
    "sourceCode": "FB",
}
followups = [
    {"LeadNo": 3678, "f_call_status": "Followup Call"}
]

result = predict_score(lead, followups)
print(result["score"])
print(result["label"])
```

## REST API

Start the Flask server after training:

```powershell
python step5_api.py
```

The API listens on `http://localhost:5000`. It keeps scores in an in-memory
dictionary, so scores are lost when the process stops.

### Health and API information

```powershell
curl.exe http://localhost:5000/
curl.exe http://localhost:5000/health
```

### Score a new lead

The API body is an object containing `lead` and an optional `followups` array.
It is not the same shape as the single-lead CLI file. Create a JSON file such
as `score_request.json`:

```json
{
  "lead": {
    "LeadNo": 3678,
    "InterestLevel": "Medium",
    "sourceCode": "FB"
  },
  "followups": [
    {
      "LeadNo": 3678,
      "f_call_status": "Followup Call"
    }
  ]
}
```

Then call:

```powershell
curl.exe -X POST http://localhost:5000/score `
  -H "Content-Type: application/json" `
  --data-binary "@score_request.json"
```

### Available endpoints

| Method | Endpoint | Purpose |
| --- | --- | --- |
| GET | `/` | API information and route descriptions |
| GET | `/health` | Liveness check |
| POST | `/score` | Score and cache a lead for the first time |
| PUT | `/score/<lead_id>` | Re-score a lead and return the score delta |
| GET | `/score/<lead_id>` | Get a cached score |
| GET | `/scores` | List cached scores, hottest first |

Example update and retrieval:

```powershell
curl.exe -X PUT http://localhost:5000/score/3678 `
  -H "Content-Type: application/json" `
  --data-binary "@score_request.json"

curl.exe http://localhost:5000/score/3678
curl.exe http://localhost:5000/scores
```

## Score tiers

| Score | Label | Recommended action |
| ---: | --- | --- |
| 80-100 | Very Hot | Contact immediately |
| 60-79 | Hot | Follow up within 24 hours |
| 40-59 | Warm | Continue regular nurturing |
| 20-39 | Cool | Re-engage with a fresh offer or information |
| 0-19 | Cold | Low priority; revisit later |

Scores are clipped to the model's supported 0-100 range by the prediction
workflow.

## Troubleshooting

| Symptom | Resolution |
| --- | --- |
| `No leads downloaded` | Check `USERNAME`, `PASSWORD`, URLs, network access, and API response format. |
| `FileNotFoundError` for `features.csv` | Run `python step2_feature_engineering.py`. |
| `FileNotFoundError` for the model | Run `python step3_train_model.py`. |
| Missing or unexpected feature values | Inspect the raw JSON and update the field mappings in `step2_feature_engineering.py`. |
| `ModuleNotFoundError` | Activate the same environment used to install dependencies, or run `.\venv\Scripts\python.exe ...` explicitly. Install the packages listed above if they are missing. |
| SHAP charts are missing | Install the optional `shap` package and retrain. |
| API returns 404 for a cached score | POST or PUT the lead first; the API store is process-local. |
| Port 5000 is already in use | Change the `port` value in the `app.run(...)` call in `step5_api.py`. |

## Retraining and future improvements

- Re-run steps 1-3 whenever new CRM data or followups should be included.
- Replace the proxy score with verified conversion or sales outcomes when
  labeled data becomes available.
- Move the API score store to a persistent database before production use.
- Move credentials to a secret manager or environment-based configuration
  instead of keeping them in the script.
- Add automated tests and a dependency lock file when the deployment workflow
  is formalized.
